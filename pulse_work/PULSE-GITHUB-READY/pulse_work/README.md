# PULSE

> **El mundo, en tiempo real.** — _The world, in real time._

An interactive 3D Earth that visualises geolocated news worldwide, down to
administrative divisions (states, provinces, departments, regions, prefectures)
and cities. Built as a production-shaped, scalable base you can later wire to
real news providers.

```
country  →  administrative_level_1  →  administrative_level_2  →  city  →  coordinates
```

The location model is deliberately generic: not every country has "states", so
the app never assumes country-specific terminology.

## Features

- **3D Earth** (Three.js / WebGL): sphere with day texture, bump, soft
  atmosphere, starfield, smooth auto-rotation and OrbitControls (mouse, touch,
  pinch-to-zoom).
- **Administrative drill-down**: country → admin-1 → city, with real Natural
  Earth geometry loaded lazily per country.
- **Level of detail**: national borders when zoomed out, admin-1 polygons when
  zoomed in, finer divisions when available. Nothing heavy loads up front.
- **News markers** with category colours **and** icons/text (never colour alone),
  clustered so nearby stories never pile up; recent stories pulse.
- **Filters** by category, a **timeline** (LIVE → 7 days) and a **global
  dashboard** with neutral figures only (no rankings or judgements).
- **Search** across countries, regions, cities and news; selecting a result
  flies the camera smoothly to that location.
- **Event grouping**: several outlets covering the same happening collapse into
  one event, while every original source link is preserved.
- **Verification status** per story: verified / source available / imprecise
  location / unverified. Precision is never faked.
- **Realtime** updates via SSE with an automatic polling fallback.
- **i18n** (es, en, fr, pt) with a `TranslationProvider` seam for later.
- **Accessibility**: keyboard navigation, ARIA labels, reduced-motion support,
  WebGL fallback, contrast-safe palette.
- **Resilient**: a failing provider or API never breaks the app; it degrades to
  a clear message and keeps the rest working.

## Architecture

```
┌──────────────────────────┐        ┌──────────────────────────────────────┐
│        Frontend          │        │              Backend                 │
│  Vite + TypeScript       │        │  Node + Express + TypeScript         │
│                          │        │                                      │
│  Globe (Three.js/WebGL)  │  REST  │  Providers ─┐                        │
│  Markers + clustering    │◀──────▶│  (demo,      │  normalize → dedupe   │
│  Panels / dashboard      │  SSE   │   NewsAPI,   ├─ classify → geolocate  │
│  i18n, state store       │        │   RSS)      ─┘  cache → realtime hub  │
└──────────────────────────┘        └──────────────────────────────────────┘
        │ static assets                       │ API keys (server only)
        ▼                                     ▼
   Vercel / Netlify /                     Any Node host
   Cloudflare Pages                       (Fly, Render, Railway, VPS…)
```

The backend owns all secrets and heavy work (fetching, normalising,
deduplicating, classifying, geolocating, caching). The frontend never sees an
API key.

## Installation

From the repository root:

```bash
npm install
```

This installs the root tooling plus the `frontend` and `backend` workspaces.

Generate the geographic datasets and textures if they are not already present:

```bash
npm run geo:build          # Natural Earth → /data
node scripts/build-textures.mjs   # NASA Blue Marble → frontend/public/textures
```

Both scripts are idempotent and cache downloads in `.cache/`.

## Environment variables

Copy the example files and fill in only what you need:

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

### Backend (`backend/.env`) — secrets live here only

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `8787` | HTTP port |
| `HOST` | `0.0.0.0` | Bind address |
| `NODE_ENV` | `development` | Environment |
| `CORS_ORIGINS` | `*` | Comma-separated allowed browser origins (`*` dev only) |
| `DEMO_MODE` | `true` | Serve clearly-labelled DEMO DATA |
| `REFRESH_INTERVAL_MS` | `90000` | Aggregation cadence (provider-dependent) |
| `RETENTION_HOURS` | `192` | In-memory retention |
| `NEWS_API_KEY` | – | NewsAPI-compatible key (optional) |
| `ENABLE_GDELT` | `false` | Enable GDELT enrichment (keyless) |
| `RSS_FEEDS` | – | Pipe-separated authorized RSS URLs |
| `TRANSLATION_API_URL` | – | Your TranslationProvider endpoint |
| `TRANSLATION_API_KEY` | – | Translation provider key |
| `GEO_DATA_DIR` | `../data` | Geo dataset directory |

### Frontend (`frontend/.env`) — public, build-time

| Variable | Default | Purpose |
| --- | --- | --- |
| `VITE_API_BASE_URL` | same-origin | Backend base URL when not behind the same origin |

> **Never** put secrets in `frontend/.env`: Vite inlines `VITE_*` variables into
> the browser bundle.

## Configuring news providers

`backend/src/providers/index.ts` builds the active provider list from config:

1. **NewsAPI** — added when `NEWS_API_KEY` is set.
2. **RSS** — added when `RSS_FEEDS` is set.
3. **DEMO** — added when `DEMO_MODE=true` **or** no live provider is enabled.

Each provider is isolated: one failing source never blocks the others.

To go live:

```dotenv
DEMO_MODE=false
NEWS_API_KEY=your_key_here
RSS_FEEDS=https://feeds.bbci.co.uk/news/world/rss.xml|https://www.aljazeera.com/xml/rss/all.xml
```

If every live provider fails, the service reports `degraded: true` and the
frontend shows “Servicio de noticias temporalmente no disponible.” without
breaking the globe.

## Adding a new news source

1. Create `backend/src/providers/<name>.provider.ts` implementing
   `NewsProvider` (see `providers/types.ts`):

   ```ts
   export interface NewsProvider {
     readonly id: string;
     readonly name: string;
     readonly origin: 'live' | 'demo';
     isEnabled(): boolean;
     fetchLatest(since?: string): Promise<RawNewsItem[]>;
   }
   ```

2. Return raw items; the shared pipeline normalises, deduplicates, classifies,
   geolocates and caches them for you.
3. Register it in `createProviders()` in `providers/index.ts`.

## Adding a language

1. Copy `frontend/src/i18n/locales/en.ts` to e.g. `ja.ts` and translate values.
2. Add the code to `LocaleCode`, `AVAILABLE_LOCALES` and the dictionary map in
   `frontend/src/i18n/index.ts`.

Missing keys fall back to English, so a partial dictionary is safe to ship.
Source text is always preserved in its original language; translation is an
opt-in layer (see below).

### Translation layer

`backend/src/services/translation.ts` exposes a `TranslationProvider` seam.
Configure `TRANSLATION_API_URL` / `TRANSLATION_API_KEY` to connect LibreTranslate,
DeepL, an AI model or your own service. With no provider configured, the API
returns the original text and the UI shows the original language.

## Updating geographic data

```bash
npm run geo:build
```

`scripts/build-geo.mjs` downloads public-domain **Natural Earth** data and
writes compact, lazy-loadable datasets into `/data`:

- `countries/index.json`, `countries/borders-low.json` (110m),
  `countries/borders-mid.json` (50m)
- `regions/index.json` + `regions/{ISO2}.json` (admin-1, simplified)
- `cities/index.json` + `cities/{ISO2}.json`
- `meta.json` (provenance, counts)

Geometry is simplified topology-preserving with **mapshaper** so shared borders
stay consistent and payloads stay small. Re-run any time to refresh from source.

To change resolution or add levels, edit the `SOURCES`/simplification settings
at the top of the script.

## API reference

Base: `/api`. All endpoints are read-only.

| Method & path | Description |
| --- | --- |
| `GET /api/news` | Filtered list. Query: `country`, `region`, `city`, `category`, `since`, `q`, `limit`, `origin` |
| `GET /api/news/latest` | Newest items; polling fallback for SSE (`limit`, `since`) |
| `GET /api/news/:id` | A single item |
| `GET /api/events` | Grouped events (duplicates collapsed) |
| `GET /api/events/:id` | One event with all its sources |
| `GET /api/countries` | Country metadata + live counts |
| `GET /api/regions/:country` | Regions of a country + counts |
| `GET /api/regions/:country/:region` | Cities of a region |
| `GET /api/search?q=` | Countries / regions / cities / news |
| `GET /api/stats` | Global dashboard figures |
| `GET /api/status` | Provider + freshness status |
| `GET /api/stream` | SSE realtime channel |
| `POST /api/translate` | Optional translation (only if configured) |

### Administrative IDs

IDs are stable and consistent:

```
MX           country          (ISO 3166-1 alpha-2)
MX-TAM       administrative_level_1  (ISO 3166-2 where available)
US-TX, US-CA, BR-SP, JP-13 …
```

This lets the app relate `news → city → region → country` without relying on
textual names.

## Demo mode

`DEMO_MODE=true` (default) serves fictional stories, every one clearly marked
**DEMO DATA** in the UI and tagged `origin: "demo"` in the API. Demo data is
never presented as real news. It lets you exercise the globe, regions, markers,
filters, search, panels and animations with no API keys.

## Realtime and freshness

- The backend aggregates on `REFRESH_INTERVAL_MS` and pushes new items to the
  frontend over **SSE** (`/api/stream`).
- The frontend prefers SSE and **falls back to intelligent polling** of
  `/api/news/latest` (e.g. on platforms that do not hold long-lived
  connections).
- Effective freshness depends on the upstream provider. Public feeds are
  typically polled every **1–5 minutes**; this is stated in the UI, not hidden.

## Performance

Priority order: **fluidity → stability → fast load → visual quality.**

- Lazy loading + dynamic imports for geo data and the globe.
- Web Worker for marker clustering; clustering re-runs as the camera moves.
- Level of detail for borders (low/mid) and textures (1k/2k/4k).
- Instanced/point markers, frustum culling, debounce/throttle, request caching.
- Automatic **device performance tier** (`utils/perf.ts`) reduces texture size,
  particle count, border detail and effects on slower devices.
- Code splitting: Three.js is a separate chunk.

## Accessibility

- Full keyboard navigation and visible focus rings.
- ARIA labels on controls, panels, dialogs and the canvas host.
- Categories use **icon + text**, not colour alone.
- `prefers-reduced-motion` and an in-app toggle disable non-essential animation.
- WebGL fallback message when 3D is unavailable.

## Deployment

The frontend and backend deploy **separately**. A static host cannot run the
backend.

### Frontend → Vercel / Netlify / Cloudflare Pages

- Build command: `npm run build --workspace frontend` (or `npm run build:frontend`)
- Output directory: `frontend/dist`
- Set `VITE_API_BASE_URL` to the deployed backend origin (or proxy `/api` and
  `/geo` through the platform so requests stay same-origin).
- The geo datasets are copied into `dist/geo` at build time.

Example `netlify.toml`:

```toml
[build]
  base = "frontend"
  command = "npm run build"
  publish = "dist"
```

### Backend → any Node host (Fly.io, Render, Railway, VPS, container)

- Build: `npm run build --workspace backend`
- Start: `node backend/dist/index.js` (or `npm start` from the root)
- Set the backend environment variables (including any API keys) on the host.
- Set `CORS_ORIGINS` to your frontend origin(s) in production.
- SSE requires a host that supports long-lived connections; otherwise the
  frontend automatically polls.

## Security

- API keys are read from environment variables **on the server only** and are
  never sent to the browser.
- External/news content is rendered as **text**, never injected via `innerHTML`.
- Only summaries/snippets permitted by the source are shown; every story links
  out to the original article — full articles are never copied.
- Incoming external data is treated as untrusted and normalised/validated
  (Zod) before use.
- Set a restrictive `CORS_ORIGINS` in production.
